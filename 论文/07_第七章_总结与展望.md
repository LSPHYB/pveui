# 第七章 总结与展望

## 7.1 论文工作总结

随着云计算技术的发展与轻量级虚拟化技术的普及，基于私有云平台构建教学与实训环境已成为高校 IT 基础设施建设的重要趋势。Proxmox VE（PVE）作为一款优秀的开源服务器虚拟化管理平台，提供了强大的底层计算、网络和存储能力。然而，原生 PVE 面板侧重于底层硬件资源调优，缺乏针对教学实验场景的业务逻辑抽象与细粒度权限控制。为此，本文设计并实现了一套基于 PVE 的私有云集群管控与教育实验辅助系统。

在系统的研究与开发过程中，本文主要完成了以下核心工作：
1. **PVE 虚拟化接口的轻量级重构与封装**：以 Django 为后端基础，利用 API 代理与 WebSocket 隧道技术，对 PVE 集群底层的虚拟机克隆、启停、网络拓扑生成以及原生 VNC/WebSSH 控制台建立等核心功能进行了 RESTful 规范的二次封装与隔离，为上层业务提供了安全、简便的资源调度接口。
2. **细粒度角色权限模型与系统审计机制构建**：基于 RBAC（基于角色的访问控制）模型，结合多级组织架构与角色分类，设计了严格的 API 路由级权限校验防线。同时，通过自定义中间件实现了从发起到响应的全链路操作日志审计机制，确保了平台数据读写的合规性与可追溯性。
3. **沉浸式实训环境与教学闭环管理模块开发**：针对教学场景开发了从实验发布、模板自动化克隆到分发的一站式授课模块。在学生端创新性地集成了“终端操作+报告编写”同屏双栏的工作台（内嵌了 Markdown 富文本编辑器与 xterm.js 智能终端），并实现了作业的自动定时保存与精准防逾期校验，打通了“布置-实验-提交-批改”的线上闭环。
4. **基于 RAG 技术的大模型智能辅导集成**：引入大语言模型（LLM）赋能实验答疑环节，利用检索增强生成（RAG）技术，将上传的实验指导书解析为向量化知识库（ChromaDB）。在学生提问时，系统动态检索相关上下文并注入 System Prompt 中，有效抑制了模型幻觉，使其能够基于本地知识手册给出准确且具有针对性的操作指引。

## 7.2 系统存在的不足之处

由于受限于开发周期与硬件资源，本系统在全面性与容错性方面仍有进一步完善的空间，主要表现在以下两点：
1. **高级集群存储组件的纳管深度不足**：目前系统主要纳管了 PVE 集群的基础网络配置与本地文件系统。对于企业级高可用场景中高度依赖的分布式存储架构（如 Ceph），因其配置逻辑的复杂性，目前尚未在系统前后端中实现深度的视图化封装与参数调优功能。
2. **缺乏多渠道主动告警与自动化巡检机制**：当前系统的异常监控主要依赖于用户在 Dashboard 中的被动数据查看与图表渲染。对于虚拟机集群资源枯竭、容器失联或异常关机等突发状况，尚未接入钉钉、企业微信等第三方 Webhook 推送渠道，缺少一套具有即时性和静默值守能力的自动化预警模块。

## 7.3 未来功能展望

结合当前云原生技术的快速演进以及智能运维（AIOps）的发展趋势，本平台在未来的系统迭代中计划向以下三个方向进行技术探索：
1. **异构云原生底座的融合纳管（Kubernetes 扩展）**：在现有管理 QEMU 虚拟机和 LXC 容器的基础上，未来计划通过深度适配打通 Kubernetes 接口。使系统能够下发和编排隔离度更高、启动更轻量的 Docker 容器或 Pod，为开发者提供双轨制（重核虚拟机与轻量级容器池）的并发实验算力选择模式。
2. **集成底层全链路数据灾备体系（PBS 联动）**：为进一步确保教学实验平台的数据安全，未来可尝试与 Proxmox Backup Server（PBS）进行系统级接口集成。实现对全量实验模板、重要节点系统的计划性冷热备份和增量数据快照同步，建立具备抗毁异地容灾级别的教学平台数据保留策略。
3. **探索 Agentic AI 面向运维操作的自主执行能力**：在具备上下文 RAG 问答的基础上，进一步提升 AI 管家的行为边界，使其向具备底层执行操作能力的智能体（Agent）进化。通过对安全操作指令集（如网络重置、基础服务重启）进行严格的 Token 授权约束，允许语言模型解析学生意图后自主调用 PVE 调整命令，完成基础报错抢修，真正实现具备一定自愈拯救能力的教学陪伴系统。
