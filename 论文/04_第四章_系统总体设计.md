# 第四章 系统总体设计

在明确了系统需要解决的核心痛点和各模块边界之后，本章将从宏观架构组织着眼，对虚拟化云管平台进行系统的总体设计。本章涵盖支撑整个平台运作的基础拓扑与概念模型，包括前后端分离架构脉络、各大系统功能模块的具体逻辑切分、承载状态流转的数据库建模结构，以及内外部接口进行通信路由的关键规则与约定。

## 4.1 系统整体架构设计

本平台秉持“高内聚、低耦合”的设计哲学，整体架构从逻辑上严格划分为三层结构体系，自上而下依次为：前端交互展现层、后端中枢业务代理层与底层虚拟化基础设施服务层。这三层结构通过规范化的内部与外部 API 隧道进行数据双向绑定，形成了一个有机联动的闭环。

**（1）前端交互展现层 (Presentation Layer)**
系统最外层，承担对终端运维人员、教师与学生的各种指令接收与视图展示任务。在现代浏览器端，通过 Vue 3 渲染出包含动态仪表盘、虚拟机资源池表格、网段拓扑白板以及在线 Markdown 报告代码编辑器等复杂 DOM 元素。当用户触发如“开机”、“克隆虚拟机”或配置“VLAN 隔离”等操作时，前端层的 Axios 请求引擎与 WebSocket 连接通道会将用户意图转化为序列化的标准 JSON 数据包，随后向平台后端的统一接入中继网关提交。此外，前端还需承担如无缝接收渲染流式的系统报错提示和持续捕获的大语言模型（AI Assistant）问答码流等被端侧驱动的长链接回显任务。

**（2）后端中枢代理与业务层 (Business & Proxy Layer)**
搭建在具有绝佳并发特性的 ASGI 异步 Django 5 引擎之上，扮演整个系统的“大脑指令中枢”与“权限隔离闸门”的双重角色。所有外部进入该层的 HTTP 与 WebSockets 握手请求在到达具体的业务代码前均须经由全局中间件 (Middleware) 执行极其严格的 SimpleJWT Token 回收校验以及基于多级角色的 RBAC 资源路由拦截筛查。
当身份校验与放行通过后，代理业务层将依据请求的动作性质进行引流：
- 偏向上层业务级状态计算的动作（如：系统添加新设一个教务学院记录、向指定班级下发一份特定带有计分板规则的 Markdown 实操说明指导任务书等）将被直连送往数据持久化层（主要是 MySQL 数据库），通过 Django ORM 完成底层数据的对象化 CRUD （增删改查）落库。
- 偏向下层集群强基建变更与管控调度的动作（如：要求克隆一个带有指定 LVM-thin 预配置的 LXC 轻机容器）则会被系统内的 `PVE Async Proxy` 核心调度模块截流。代理模块会使用系统预配的 PVE 超管票据池，将其组合为合乎原生安全验证规则（如带有 Ticket 首部及 CSRF 防伪戳）的 REST 原生请求包，随后代替普通用户向下方的私密隔离网络管理端点自动安全地提交执行工作，并负责将长耗时的异步 Task UUID 进行挂起轮询追踪。

**（3）底层基础设施与周边协程引擎层 (Infrastructure Layer)**
处于平台安全网络拓扑的最底端封闭区域。其中囊括了由若干搭载着 KVM/QEMU 等全虚拟化、LXC 容器架构以及 Corosync 集群通信组件物理宿主机所共同拼凑支撑的 Proxmox VE 集群计算底盘；此外也包括了用于辅助提供本地部署大模型回复能力逻辑流节点（LLMs Services）及向量内容查询组件，以及部署来挂载处理特别耗时、或者具有高延时的后台重负载清算任务（例如夜间大规模克隆操作补偿以及镜像自动化同步下载备份作业）的异步执行生态链引擎（如基于 Celery Worker 并挂接 Redis 充当消息队列的高性能工作队列服务器群）。针对这些底层算力和通信枢纽，系统不会作任何公网可嗅探暴露端口供给前端设备直接通讯穿透。

## 4.2 系统功能模块设计

依据第三章的功能调研抽离结果，本系统在工程落地上被剥离划分为五个互相联系支撑却又能在部署与测试逻辑上彼此解耦解绑的核心功能块区：

### 4.2.1 PVE 基础资源与网络拓扑可视化模块设计
负责 PVE 原生物理层资源清点与基础共享存储池的贯通展示通道，是基础基建底座。
- **计算节点健康状态子模块**：对所有 PVE Node 本地节点的硬盘健康度指示灯、磁盘阵列负荷、CPU/内存的即时消耗、内部心跳存活及稳定组网情况执行高频快照及呈现汇总。
- **模板集散地及 ISO 仓储共享管理子模块**：提供对内部及独立外部支持长传和断点续存的各类镜像光盘（ISO包）资源以及高密度配置的克隆基础容器模板（CT Templates / QEMU Templates）实现增删改以及元信息注记改动控制面板。
- **网络拓扑与网卡可视化子模块**：管理员利用图形连线的拖拽白板设计工具（LogicFlow集成），勾画下层底层 Linux 桥接模块（vmbr，虚拟交换机）与 OVS（Open vSwitch）关联配属设计及物理网卡透传流，极大降低集群内网串连发生广播风暴及错误 IP 子网网段引发的主机网关冲突安全事件概率。

### 4.2.2 虚拟机与容器集群调度模块设计
云系统的第一主责，直接面对并化解来自前端的最具并发性访问与复杂的集群操作交互：
- **容器与虚机配装分配流水线**：接管解析前端层级的涵盖处理器结构 (vCPU Sockets)、热添加内存界限及 NUMA 相关绑核、多队列网卡、VLAN 通道等高度结构组合属性表单阵列，负责转换适配为对 PVE 原生架构进行实例启动下达和配装更新指令翻译机。
- **全生命周期维护协调控制极板**：承担针对被选定虚拟机或者容器实例其上存在的全部状态周期的按钮电源动作操控：挂起休眠唤醒、彻底中止清理及诸如系统只读快照捕捉创建（用以一键还原）、恢复快照以及对系统扩盘参数的热变修改干预。
- **集群异步任务轮询记录器 (Active Task Queue)**：当系统涉及如转移物理硬盘 (Migration) 动辄上百 GB 时长等底层长操作作业进程，模块启动依托回调池子的异步任务跟踪列表追踪。其可保证即使 Web 前端因故掉线再连，操作流水也绝对能够在记录中心持久被后台跟踪到底直至异常抛弃或是执行闭合圆满完成。

### 4.2.3 实验管理与教学辅助追踪模块设计
脱离基础 PVE 原生属性，转为专用来深耕教师与实操学生双分角色协同工作的独立重度应用业务空间。
- **大规模授课环境流水派发流**：专门面向任课教师。系统容许将特定的模板镜像挂钩特定的一门前序教学科目。教师通过圈定具体已规划进数据库的自然班级学号或院系专业人员清单，模块则接管启动高并发克隆派送工作。系统为受分发学员的账号各自构建对应的唯一虚机副本配置与鉴权围栏边界关联。支持随时基于科目开辟和解算来激活这批上百台专属练手的虚拟资产启动和收缴清算下线功能。
- **分屏沉浸式试验与计分板查阅大厅**：把复杂的 Web VNC 穿透窗口、或者交互终端 (Web Terminal SSH/Bash 命令行) 置入到与系统本身携带集成的带有 Markdown 渲染及含各类主流编程语言代码高亮识别富文本手写板在同一视窗的工作台上。以实现在实战终端对练后当场保存验证结果。结束后的整卷资产则投递转入打分队列流程开放给其导师审批并直接给出系统关联评分并通知通告学生端。

### 4.2.4 树状组织架构与多级 RBAC 权限管理平台设计
- **层级身份人员节点同步管理树**：维护一套灵活能够上下溯及且无无限扩张层级的复杂大部类管理树，非常适配从高阶企业至基层业务员或是类似于复合交叉学院的高校学籍管理需求编织出身份组织网图。
- **精细角色分配-前后侧资源拦截调度器**：核心安全阀网。在其中支持用字典方式定制若干可配置角色的行为图集。无论是前台左边或头上渲染展现的一级和子级二级列表、弹框内的关键审批提交按钮的暴露亦或者隐藏，甚至是在最核心内部 API 提供拦截网的地址白黑白正则匹配路径树（Regex API Policy_URL_List_Checker）。所有的请求会在此作判断过滤以断开用户任何横向与提升越权的黑客意图行径动作。

### 4.2.5 系统监控、接口级操作审计流水记录模块设计
作为常驻云平台的守望先锋角色。
- **核心遥测引擎与实时汇流仪表**：收集模块依靠无需打扰底层且超轻量化的主动节点状态爬取，对上千台设备的集群网络交换封包规模走势、算力与集群磁盘总储存池消耗指标形成不间断的数据源推送墙；借此构建大盘中心酷炫且精准的大脑图。
- **操作行踪留痕入库拦截钩子**：将各类非无害的只读查询调用外涉及到底池资源结构物理增加篡改的活动踪迹，包括修改学生实验配置、开关或误操作强制注销等指令都拦截并拆分压入系统自身数据库特定的日志表留查备案表形成不可单方撤回和抵赖的信息凭据凭据机制链条。
- **基于 RAG 搜索智能 AI 导调聊天框辅助（可独立外接）**：一个外扩功能插件，对接部署后的诸如通用或者本地调优后的大型号交互文字推演类基座网络，借用内置私库数据辅助帮助排查日常简单的 Linux 发行版与 PVE 云平台的命令常识，通过流出答疑的对话气窗解散极大数量的常识阻碍，增加可用率。

## 4.3 数据库设计

有别于虚拟机的硬资源实际磁盘存放的 PVE (Corosync Distributed Configs) 生态分布层机制，关系型数据库系统的首要目的更偏向基于人财物关系的维护构建以及针对高复杂应用管理数据的抽象记忆承载器。平台使用在行业享有性能声誉极高且部署体量巨大被高度调优下的 MySQL 服务节点来扛此重头应用数据库角色重任担当。

### 4.3.1 数据库概念模型设计
我们通过建立物理世界的关系规则和映射模型（ Entity-Relationship Model, 及 E-R 模型关联建立 ），系统内的这套机制得以顺利进行运转。
1. **系统高权权限管控模型链路结构 (User - Role - Permission_Menu/Resource API)**：作为所有内部动作前置合规性的安全堡垒判断底板。首先【账户体系实体】(User) 通过独立分离设定的挂载节点可以绑定多项层级下的各自独特维度的【身份组角色群】(Multiple Role groups)。而处于组上的角色体系在下级对应挂在了被配置为可见或是可执行调用修改能力的具体复数群规模的【前端 UI 展示元素块视图 / 后端严密请求 URL 入口字典】(Resource and API Scope Entities)。只有在一条完整的交集比对校验通过链路上，才能准予合法调配行使后续对 PVE 与教育操作体系数据库更改干涉管理。
2. **实验全周期的教学流对象交互关联线 (Experiment Template Model - Task Distributions - Evaluation Reports)**：首先有权力者（例如开课讲师或者高管）规划下放一门具体的带资料包和要求的【课堂实践教学指南项目体系】 (Course Entity Model)，此模型内部强制要求锁定捆绑指定好了一个作为环境复刻模具的 PVE 克隆用【虚拟基石样本映射】(Vmid Standard Mother Template Mappings)。当讲师确立派发，这门总课程会裂解分发给指定的多位【学生账户实体】(Student IDs)。学生依照关联执行的交互环境操作记录内容，随时间转化为持久留存的【结果答卷与成绩批阅结果报告单】(Lab Reports and Grading System Entities)。
3. **PVE ID 与系统隔离缓冲字典对齐结构 (Sys UID & Raw Pve Info Mappings)**：这是极其特殊且是构建 PVE 与外设对接平台极其必要的处理思路抽象设计模块。考虑到自带开源 PVE 整个架构分配虚拟资源的时候（采用形诸如 `100`, `105` 类似的数字标识作全局标示定位码），这种原生结构遇到本需要挂载异地另外 PVE 集群或者在日后集群遭受不可逆物理机器彻底抹除需要备份重构数据找回恢复重载情况系时是致命灾难。故此设计引入系统专设的内网字典分离层架构模型。在该模型架构内：任何受本系统接管下辖以及新生成的每一只计算实体或网络分配都具有本身的一个强一致且完全独特的内部主键全球唯一辨识标记（System Internal UUID），随后通过这一 UUID 作为与该时刻真正运作着的某个具体外部 PVE 环境中某一实体主机标号 `PVE Vm-id Number` 和 其当前停留栖息的实体宿主机机器 `Server Node Info` 的一个松耦合关联锚定映射联系关系网络链结构。

### 4.3.2 数据库逻辑表结构设计
经过 E-R 模型中对应的一系列强制依赖范式以及查询高效性原则抽象后落实形成主要的、具备关联的主导业务核心关系基础表单建立：

1. **`sys_user` (系统全局管理与身份库基表)**：持久容纳基础身份的源文件。设定有形如 `user_id` 为全局递增序列主属性，还携带诸如 `username` (可以是学号或者是认证登录的特定唯一员工字符串识别代码)、强防卫 Hash 型加盐保存字段 `password_hash`、隶属于管理网格哪一块体系结构的外部键映射码 `department_node_fk`、最后活动通信及限制拉黑名单标记 `is_active_blocked`。
2. **`sys_role_menu_assignment` (联合鉴权菜单访问交叉映射授权中层分配数据大表)**：配合解决角色对于视图请求和动作拦截的交叉覆盖判断重重交织重叠问题而构建。内置包括设定了诸如角色指引代码的 `role_sign_uid` 和被配置管辖分配了能够到达与操作视图层呈现代码表符的 `component_route_name`, `api_uri_prefix_match_regex` (这是一条用于在后端提供极高判定级别网关路由权限字符串的精准截取或放行控制规则识别特征段), 以及为了前台界面展示而附设的例如 `is_visible` 特殊标记位。
3. **`pve_resource_abstraction_pool` (内部计算池系统实体镜像缓冲表单)**：承载前面模型叙说的缓冲脱敏分离概念。包括核心索引键 `platform_self_uuid_pk`，指向该台具体生成设备拥有、隶属以及控制权下发控制人员外键约束键码 `bind_owner_person_uuid_fk` (用来阻隔即使同学登录同一个局域网也没权限干群对方机体的物理原因层隔离)。还具备详细保存对具体某个物理底机如 IP/物理机名字定位寻址参数的 `physical_worker_node`，以及此刻挂载在被管理的 Proxmox 内最真实纯净的原始标号码 `qemu_raw_hypervisor_vid`。
4. **`edu_practice_lab_reports` (沉浸互动成绩评估表)**：支持双边大教育平台运作的数据载具结构账薄。涵盖字段列举如用以精准追查这是来自于哪一堂教学体系实验项目的任务编码 `task_project_class_fk`，内容字段由于包含了带有极高文字数量和可能的 Markdown/Html/Base64 图片数据块结构编码必须设置为非常能储存的大规模字符长结构载体储存区类型块如 `LongText_Rich_Content` 结构字段。及后续包含成绩批阅落袋判定 `evaluated_score_integer_mark` 级评等附属判定参数字段群。
5. **`sys_auditing_behavior_log` (全操作日志安全巡检防抵赖审计归档只写特制表体系)**：此数据库表非常独特，它的建立本身几乎不接纳除了超级管理员之外的更新或者编辑指令请求处理机制。存储诸如能够识别追寻线索源头的 `action_perpetrator_id_fk` (指代由谁按下的引起操作波澜或改变的破坏性/非破坏性查询触发的人员编码标识)、触发操作具体归属哪一类动作描述词组的 `behavior_description_action_title` (举例说明:"非法提权越级探索阻断失败", "重置 1 班全体的特定虚拟资源快照复原操作")，来源连接的通讯握手 IP 段标记 `incoming_handshake_source_ip` ，甚至囊括针对特别风险改动的具体传递进去服务器端引发改变的数据封包体全文保存串 `request_payload_json_snapshot` 用来应对未来被随时倒推查证追踪还原和故障追定源。

## 4.4 接口交互与通信规则设计

为了兼顾系统操作前后台各种常态报表与属性更改的高频敏捷调度和低负载状态；并在此基础之上也能极其从容化解面对那些属于要求极高并发以及有极度长等待交互时序要求或者长效阻塞连接保持通讯和具有极其强烈的流式推送反馈通讯痛点需求环境体系；在此这套重前端 SPA 重型结构的系统底层与服务器服务端体系搭建与建立沟通之间的管道构架被非常精巧得明确且坚固定义成了标准无状态短联请求 HTTP 框架与全双工驻留态多线路复用 WebSocket 连接两套并行机制大路线运转结构并存在模型。

1. **统一数据中心请求应答 RESTful API 架构协议与调用层标准化定义约束规范**
这部分主要旨在用来统筹用来获取某个 PVE 或部门数据列表等这类拥有立刻、即使执行或可以很快给与计算回包结果（并且通常不存在需要保持持续不断往后刷新送报连接状态性质）状态的交互环节。应用构建由于后端借用框架 DRF 赋能所具有标准化规则接口功能提供对这类情况给与了完整的支撑与限制。传输报文协议强制化为极具平台跨越优势和被前后端高度可解剖的 `application/json; charset=utf-8` 的纯字符串形态载体传递处理体系；并且前后端设计协议定格使用类似 `Access Token (Bearer xxxxxxxxxx)` 之高安全性头部密文携带鉴权包形式对所有涉及需要权限识别接口层做包裹封信防护。

- **URL API 地址路由严格且具有隔离性分发规划指导原则**：系统的地址设计摒弃了随意化和冗长的乱序堆砌。全部符合明确业务分类功能及迭代层级的标记指引与限定标识的嵌套逻辑排列。形如下结构示范展示：诸如关于最根本密码重设获取系统令牌权限类的路由需统一放给 `/api/v1/auth_core/...` 统筹网关管控去提供；面向底层向 PVE 真实机体或者容器发生如强制重启或添加修改系统桥接新设定相关的调度指令归口限制流入到形如 `/api/v1/pve_infrastructure_dispatch/...` API区段内请求通道去统一控制执行；而对像比如新建课堂并把对应的模板分配至全体系班级所有的普通使用参与学生等专门业务教务分发动作则全部交由和约束控制在 `/api/v1/education_business/...` 等类路由分流隔离处理体系网管区域里。

- **数据层固定包体反馈框架回传结构 (Stable Response Wrapper Formats)**：为方便且统一解决由于海量多级复杂的各式前端 Axios 层中出现的众多难以拦截和分辨不同接口可能五花八门的业务返回结构错误、或是数据承载层层解析麻烦与抛异常灾难发生等痛苦的前级工作环境难题体系应对策略：后端中控平台会通过一个极其严苛统一的中间件系统结构对所有无论其正常或者是内部处理产生故障异常情况结果强行穿上了一件标准的回复结构包装套皮（Wrappers）。这确保无论何时收到回复均含有基础判断定位标准架构集形如包含诸如： `{ "code": 状态定级判断码型如 200(标准达成)/400(请求缺陷)/401(令牌证照作废权限未及体系失败)... 等, "message": "一段解释型或是对上述响应明确给前端提供出类似（'用户资源执行配置项变更重写成功' 或者 '抱歉由于底层 PVE 此刻 IOPS 满负载挂起引发您的配置暂时入列无法实施等等... 等提示' 等可以帮助快速反映的明确反馈语义信息体系文本框", "data": { 这里是一个可以灵活千变万化的嵌套级的数据列表载体系如返回所被查询需要的整个虚机详单对象 JSON 群结构，抑或只是一串简单的修改反馈回显列表群载体而已的包裹群对象 } }`。这就意味着极大地给予前端利用最简单代码能写进 Axios 的总体层拦截阻断监听网兜做到了以逸待劳，例如通过统一识别只要含有外发给出的回复出现诸如特定的失效识别代码后例如上例的 401 ，即可一劳永逸将其拦截路由操作无视下发的任何层级弹框一脚直接踢送到总控登出验证页面去从新进行拿号身份刷新操作以降低极其复杂的局部故障层抛出引发页面渲染无响应甚至死机死锁循环漏洞问题现象体系可能及隐患产生条件体系产生。

2. **支持并发高容与长命链路及通道隔离订阅设计 WebSocket 高频流全双工链接通讯体系规则结构体系（Daphne Async Consumer 驻存体系及 Channel 规划分布协议配置分发点）**
这部分底层应用基础依赖搭载了全链路可支持长期在内存与处理区后台建立一直悬空而并不会引起死锁占用服务器宝贵连接请求轮训排队卡死拥堵现象事故发生的后端全体系异步化的高频收发通信环境处理基石 ASGI 层以及对应的能够实现极佳支持发布-订阅、路由映射以及借助底层超高容纳能力的群层推送缓存信息流 Redis 实现 Channel 层服务集群架构支持下的复杂多状态交互应用分流通讯网络基建方案设计：这些通道的设计完全服务且主战用来对应和接驳了诸如由于连接云端机房远端 xterm 命令指示黑框字符回显的高速反复数据丢包和收取工作以达到如亲临终端一般打字不粘粘跟手输入极高反馈即刻感受，或者是用来把复杂图像编码流不断回推在前端浏览器内画在 Html5 画板渲染的底层图形环境界面 noVNC 数据长通道以及负责和外部庞大 AI 模型聊天通道对话所急切必要的保持长连持续推字送屏解答响应机制流推送等极限重交互通信压载应用使用情景需求点。

- **脱离原生短平快验证方案引入高机动临时安全准入验证架构握手机制建立法门规章方案**：鉴别考虑到被设计标准的 WebSocket 原生通信传输发起协议自身环境天生结构并不能完美天然的支撑类似于我们常规范的常规 HTTP 通讯传输过程中去在头部自由挂附或携带能够带有授权防越级身份解密字符串（如 Authorization Bearer Headers 组合字符串身份鉴别标识）此天然缺陷。避免为系统留后门，此通道建立时该工程提出并使用了以 URL 安全携带参数的短时命且高度加密后经过脱敏处理的高速防伪单次使用换流通行证签发机制进行建立准入通信握手：也就是平台将原本持在前端用于正常处理验证的令牌系统要求通过正常短效常规端口申请类似端点比如： `/api/v1/ws_temp_authenticate_exchange_ticket/` 进行事先极速请求拦截审批然后剥落获取带有极高时效限制性的只能如（存留生命周期仅仅维持能够发生网络挥手动作短短在约合十几秒的内）暂时代开通道授权进入证票据密钥：类似形如拿换了一串类似于 `?conn_ticket=A_One_time_limited_super_fast_expiring_safe_hash_code_xxx` 携带着随后立马跟随开启发出最初的一级 WebSocket 探测和拨号沟通指令。一经检验准入后端立即打开通信挂载服务监听大门以实现通讯放行随后立刻使此鉴权作废确保不留长效连接挂载隐患通道给任何被侦听扫描截获可乘之机发生等漏洞情况。

- **网关通道信道截流归档与专项分发分类通讯架构布局路线方案配置分发细则设计分配结构与引流（Channel/Consumer Routings Allocations）**：在防伪成功后端正式将通道开启长监听工作通讯接点接管之际；为免于产生杂乱通讯冲突，后端通信路由开启内部网关分离以疏导处理不同的巨量消费队列层频道通道和请求队列方向从而引导进对用的内部通道：

  - 发往 `ws://host_address_domain/ai_llm_assistant_interactive_flow/conversation_push/` 链路通道系统的信桥沟通路径层架构：承载与承担平台前部展现对内部搭载调用或是调用部署的大基座自然回答语言文字模型层发起的（类似例如我们平时经常使用见到的 ChatGPT 对话网络使用模型一般的带有互动解答功能的提文字文本推字流功能）所使用的询问信息包投递和向后反馈回答文本内容的持续分包推码送信大长通道管网设施通道。由此能够由后部分系统在获得外向网关服务分批下分提供给予反馈的一星半点句子文字片断结果源源不停将拆装打包好的回复反馈句柄码字符段一直通过长链路向一直连接保持前端页面通道下发传送从而真正在实现获得体验了如具有所谓的文字解答等结果输出时能够达到产生带有强烈真实沉浸感的即时推送渐进式的字符动态拼写敲印上屏幕反馈感系统动态表现功能。
