# 第六章 系统测试

在系统完成了详细的设计与编码实现阶段之后，为保证基于 Vue 3 和 Django 5 的 PVE 虚拟化云管平台能够稳定投产于企业或者高效真实的教学使用场景，必须对其开展严密、系统的测试工作。本章主要阐述了平台测试环境的建立方案，并挑选了针对系统最核心安全边界及业务流的功能测试用例进行白盒与黑盒的验证流程剖析。

## 6.1 测试环境搭建及测试工具

为了精准模拟平台生产环境下的网络和业务操作表现，本次系统功能测试在局域网内搭建了完备的微型虚拟化实验集群。

**（1）基础硬件与部署拓扑环境**
- **底层 PVE 集群**：采用了两台高规格硬件服务器（如各搭载两颗 Intel Xeon E5，128GB 内存配置资源）作为底层独立物理计算节点。节点上部署安装了原生的 Proxmox VE 8.x 发行版，并通过千兆双链路交换机构建为同在一个 Datacenter 管理控制下的资源池群集。
- **上层云管服务器**：单独分配了一台四核虚拟机并在其上安装了 Ubuntu 22.04 LTS 作为管控系统的宿主机环境，配置好了 Redis 服务以配合 Django Channels 和 Celery 进行队列处理，安装了 MySQL 8 承担平台业务架构及流水日志的持久化，最后拉起运行后端代理中间件；前端采用 Nginx 承载 Vue 的反向代理资源下发。

**（2）测试辅助工具**
功能测试阶段以手工录入边界触发用例（即常规黑盒验收探测）为主。对于后台的接口安全与角色隔离探测，则借助常用的 `Postman` 组件手工构造含有特定 Header 凭证的伪造请求进行越权试探自动化校验。

## 6.2 系统核心功能测试用例

为验证系统核心模块的稳定性，本次测试主要挑取了能够反映本平台特色与基础架构防线的三个重要用例（含权限、指令下发与安全防篡改），以形成完整的逻辑闭环验证。

### 6.2.1 用户登录及 RBAC 访问控制测试
**测试目的**：验证系统能否安全发放 JWT 时效凭据；同时检验处于同一组织架构树下，拥有“讲师权限”的用户和仅存在“学员身份”的人员在系统前端可见功能渲染范围及后台底层接口鉴权上的严格分隔是否生效。
**测试步骤**：
1. 测试人员甲使用由超管注册好且仅分配了普通学生角色的账号 `student_A` 执行登陆操作。
2. 登录后进入控制台观察前台 UI；预期只能看到左侧唯一的“我的操作试验台”入口。随后该测试员尝试在浏览器修改 URL 或利用抓包工具强行对 `/api/v1/system_admin/get_nodes_list/` 等教师及超管级别的高权控制端发起探测请求。
**测试结果**：
系统在登录动作即刻成功校验密码并在前端无感写入长短时 Token。学生主页严格触发了 Vben 框架的路由过滤钩子，前台显示屏除无关管理菜单；随后由人工强制注入发起的获取教师私有资源的伪造探测也均被拦停，Django 内置中间件准确抛出预期的 `HTTP 403 Forbidden Access By Scope` 防线拦截反馈信息。权限鉴别与路由隔离系统工作完全符合原设计设想。

### 6.2.2 虚拟机启停、控制台唤起操作测试
**测试目的**：检验重封装过后的云控平台能否有效将用户的自然点击翻译为 PVE 底层动作信令，且验证内置的 WebSocket 穿透桥接能否安全畅连。
**测试步骤**：
1. 在拥有相应授课环境控制权教师账户下进入“容器与实例管理单”，对指定的 CentOS 试验靶机实例（例如当前状态为挂起中）点击“强行重启 (Reset)”。
2. 等待实例上电完成握手后，即刻于该条目功能组点击“接入实操终端”唤出前台集成的直连黑框。
**测试结果**：
前端 Reset 指令发派后，页面左侧列表挂起标签秒变为响应态。切至底层 PVE 日志验证，确认代理接口层代配拉起了内部的 `root@pam` 发送了对应的 `/api2/json/.../status/reset` 重置调用并得到底层回执；重置结束后页面内嵌成功弹出 `xterm.js` 画布窗口并借由 AsyncSSH 不断向游览器打印 Linux 系统启动序列日志，模拟键盘执行 `ls -al` 以及退格键等各种日常敲击也展现出了零粘连即时反馈。操作与虚拟终端链路实操无损通过测试。

### 6.2.3 审计日志溯源记录准确性测试
**测试目的**：针对系统设计中为弥补原生环境因缺乏对操作者具体记录身份而重点建设强化的追踪功能。专门进行“谁、何时、执行了越级动作”的双向防抵赖留痕检阅。
**测试步骤**：
测试人员模拟一名普通讲师跨出限定数据防线，尝试利用系统端点强行请求抹除一个并未划归其教学管辖专业的学生环境资料。失败后重新以审计超管身份切入 MySQL 查验行为追踪系统入库流转情况。
**测试结果**：
该越界操作行为被 API 数据过滤网正确弹回 403 错误警报且未被物理落地抹除任何基建数据。超管提取翻阅底层专用溯源只写表单 `sys_auditing_behavior_log` 数据流，清晰查索到刚新增了一条特定警戒类目审计记录。记录内赫然保留了当时涉事讲师内部账号 UUID、操作客户端 IP 以及被阻截退回拦截警报详情；其提交用于破坏的 Payload JSON 备份也在库单展示中一字不差供备查。审计链做到对侵扰事件与特定人员的高度不可抵赖与高保真抓存。

## 6.3 测试结果分析与总结

综合前文设计的核心操作边界探索与日常交互模拟用例，对整体研发搭建完成的虚拟化云管理应用平台实施了功能复核。测试表现结果表明：本次开发的云调度台各接口响应判定灵敏，业务线上下流转通畅；界面交互逻辑闭环完整，无异常崩溃情况。从物理算力节点的重置接轨到底层学生角色的极其受限的数据权限过滤阻断；整个被定制化深度打造的全套管理平台的需求边界在功能层面均已全部获得达标验证和落实。该系统逻辑坚固可靠，已具备成为实际学校教学场景或小微研发团队对集群管控支撑的私有云调度门户上线运行的标准要求。
