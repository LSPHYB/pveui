# 第五章 系统详细设计与实现

经过总体设计阶段的宏观规划之后，本章深入到具体的技术落地层面。围绕系统划定的各项核心业务模块，本章详细阐述如何使用 Vue 3 体系在前端进行状态维持和交互布局，以及在后端使用 Django 5 与 DRF 拆解并实现与底层原生 PVE 引擎对接的各类异步操作流及技术难点。

## 5.1 PVE 基础核心交互模块与视图渲染的实现

系统对于基座的接管是对整个集群进行操作调度的第一步，该模块包含硬件资源遥测解析及底层网络拓扑的图形化落地。

### 5.1.1 节点硬件指标监控与存储、模板体系的同步
对于 Proxmox 集群及宿主机的感知，后端利用 Python 结合 Celery Beat 构建了独立于前端 HTTP 请求的长驻循环采集服务。拉取服务以极短的阈值定时调用 `/api2/json/nodes/{node}/status` 接口。取回的数据包含 `cpu`, `memory.used` 等原生属性。后端在将其派发给前端前，利用 DRF 的 `SerializerMethodField` 进行数据的单位换算与脱敏。
在前端渲染侧，Vue 组件利用 ECharts 对接后端 `/api/v1/metrics/chart_data` 接口。通过 Vue 的 `onMounted` 生命周期钩子建立轮询或 WebSocket 订阅，将 JSON 数组推入响应式的 `ref` 序列中以动态驱动监控大屏折线图刷新。对于节点自带的存储池（如 `local-lvm`、NFS）和模板体系（具有 `template: 1` 标识的虚机），前端开发了一键式文件浏览器视图，并封装了基于 Axios 的切片断点续传器，用于大体积 `.iso` 镜像的上传。

### 5.1.2 基于 LogicFlow 的自定义网络拓扑图可视化构建
平台破除老旧系统依赖表单填写配置 Linux Virtual Bridge (VMBR) / OVS 的痛点，采用国人开源流程图组件 LogicFlow 搭建交互式的网络拓扑配置面板。
系统后端首先检索集群 `/api2/json/nodes/{node}/network` 返回的网卡结构，构建出包含物理网卡至 VLAN 子网配置的有向图 JSON 字典。前端解析该字典后，将物理网口渲染为干节点，各虚拟网桥及 VLAN 子网渲染为末端叶子节点。当网络管理员在前端面板通过拖拽连线改动网桥与物理网卡的绑定关系时，Vue 将捕获此特定拓扑变动，将更新请求以 PUT 包形式打向后端。后端鉴权后转化为 PVE `ifupdown2` 工具应用的底层参数命令重刷网络配置。

## 5.2 虚拟化实例全周期管理与批量任务引擎实现

### 5.2.1 基于 PVE API 的虚拟机与 LXC 容器异步操作流
虚拟机从创建到挂起、销毁，本质是对对应 VmId 的 `.conf` 配置及 QEMU/LXC 进程的干涉。以通过模板克隆新实例为例：
当前端提交包含虚拟机内存、核心数、IP 地址分配等参数的表单后，后端代理网关不再阻塞等待，而是将流程拆分为标准异步任务队列：首先调用 `POST /api2/json/nodes/{node}/qemu/{vmid_template}/clone`。原生 PVE 在启动克隆进程时会立刻返回 HTTP 200 及一条特异的 `UPID`（PVE运行态追踪码）。后端将此 `UPID` 锁定至系统数据库并开始循环轮询 PVE Task 状态，直至完成。随后异步进程发起下一波 `PUT /nodes/{node}/qemu/{new_vmid}/config` 配置更新与启动请求。这种非阻塞机制有效保障了操作超大规格实例时的平台可用性。

### 5.2.2 虚拟机 VNC 与 LXC SSH 双模式控制台的 WebSocket 隧道建立与 Daphne 适配
为了彻底解决 Web 端无缝回显响应的交互问题，系统通过后端网关向 PVE 申请带有 SpiceVNC/Websocket 授权票据的 VNC Ticket，并包装入本系统签发的 Token；前端 noVNC 组件读取凭据后即可建立画面穿透的加密视频隧道。
对于要求纯净指令交互的 LXC 容器与实验 Linux 靶机，平台借助 AsyncSSH 及 Django DaphneASGI 引擎构建了名为 `TerminalConsumer` 的双向中转信道。前端引入 `xterm.js`，用户每次敲击键盘（包含功能控制键），指令字节即通过 WebSocket 传递给 `TerminalConsumer`。消费者进程在内网与下属靶机建立真正的 SSH 连接，并将底层靶机抛出的 STDOUT/STDERR 通过相同通道极速推流返回到 `xterm.js` 的画布上，实现了几乎无感延迟的丝滑 Web Shell 体验。

### 5.2.3 定时任务队列 (Task) 与异步镜像下载进度追踪
应对长耗时引发卡顿的痛点，所有可能会引起 PVE 挂起阻塞的大工作（如从外部互联网拉取数十GB的操作系统 ISO 镜像、系统级全量备份）一律交与 Celery Worker 从主应用中剥离单独执行。作业运行时，Worker 脚本定时将当前如 15% 的完工进度率刷新至 MySQL 的 `pve_system_tasks` 任务追踪表中。前端仅需通过微量网络请求轮询获取自身名下该工单的记录，当显示 100% 后弹出完成提示，完全实现大型耗时操作的前后端解绑与安全进度展现。

## 5.3 实验教务管理双端协同架构的实现

### 5.3.1 教师端实验教案设计与学生环境一键配发
在授课流中，教师可建立以自然班级为对象的派送单元。在分配实验时，不仅能在前端勾选所需关联的纯净系统模板（`VM Template`），还能挂载对应 Markdown 撰写的指导书文本。完成打包点击分发后，系统依托 5.2 节所设的自动化任务引擎，通过 For 回圈并发形式，为名单内每一位在册学生定向克隆出一台仅供其个人查看并操控的虚拟机器实例，并下发特定实验指导内容及防作弊隔离网络规则，彻底释放老师手工配置百台测试机环境的压力。

### 5.3.2 沉浸式在线实验报告编辑器与 Markdown 双向批改流
学生登陆时仅能看到精简的“实验进入工作台”卡片。在进入被分配的环境后，前端采用左右分屏沉浸式 Flex 布局：左侧加载基于 noVNC / xterm.js 的靶场系统直连视窗以供真机演练；右半屏则深度加载集成了具备代码高亮、表格功能的 Markdown 控件（例如 vditor 或 monaco-editor 构建）。极简并排布局使得学生可以左侧敲击验证命令，右侧随时粘贴结果截图撰写随手报告。实验闭卷时，所填富文本由接口统一入库变为数字资产等待流转；教师从后端列表中提取已归档的内容直接同源查阅及进行分数评定。

## 5.4 智能问答大语言模型服务的融合接入

为赋予平台智能“自愈答疑”能力，系统将目前大火的大模型问答完全内嵌于运维支持环节。

### 5.4.1 基于 Chat WebSocket 的 AI 助手流式交互及交互界面呈现
受限于标准 HTTP 通信需要整体等待长文本网络思考完成才能收包的滞后性，系统采用与 ChatGPT 一脉相承的 Server-Sent Events 流式推演原理：依靠建立挂接 `AILlmConsumer` 的通道。当前端悬浮气泡抛出请求时，后端向外置的 AI 提供商发起交互换包，拿到每一句短语甚至几个生成字节就立刻用 JSON 数据流推送给 Vue 端的聊天滚动窗口。配合打字机显示效果渲染函数，达到瞬间响应及内容逐步“蹦出”的无卡顿沟通体验。

### 5.4.2 RAG 知识库构建、多模型配置与用户配额管控机制
外置公有大模型对于本校或本企业的私有 PVE 资产规则全无概念且极易发生幻觉；系统在底层融入了 RAG (Retrieval-Augmented Generation，检索增强生成技术)。管理员可以先行通过面板上传系统指导的 Word 或特有运维操作 PDF，系统服务在后台通过分词模型将其向量碎片化并打压入本地化 ChromaDB 向量数据库。此后终端在发问时，后端会自动进行近义词检索提取最高关联知识，强制约束生成的回答极度结合当前平台体系的操作规定。
此外，配合请求拦截机制，后端为每个账户绑定调用配额计费 Token 锁，阻断过度请求消耗的问题。

## 5.5 权限及安全维度的实现

### 5.5.1 后端动态菜单权限树的分发与前端路由组件 (`component-loader`) 异步加载
Vben 框架的精髓落在此处的登录鉴权结合：当学生持颁发的 Access Token 发起登陆后的第一时间；被注册在 Router Guards (全局前置路由守卫) 内的检查钩子会向后台拉取菜单；由于该用户的 RBAC 标识只是普通学生，Django 后端将直接裁切掉包含 PVE 底层设置、节点监控等菜单路径，仅回发单调的针对学生的视图名称。此时浏览器内部的 `component-loader` 函数开始执行按需懒加载；致使用户即便试图强制输入管理员路径字眼也找不到实际未被允许加载的页面包组件源码，形成坚实的基础路由隔离防线。

### 5.5.2 角色数据范围权限 (`data_scope`) 与全局接口审计拦截器 (`middleware.py`)
为防止在前端绕过入口通过发包工具越权突破，后端在涉及查询或处理资源分配表之前注入了特化的 `data_scope` 数据过滤机制；若带入了没有负责权的年级标识去请求，将即刻抛出 `403 Forbidden Data Block`。
而所有在平台发生的大部分写入修改行为，也会经过专有定制编写于 `middleware.py` 的钩子引擎，不留死角地把执行人号，IP 信源，特定端点请求与所携参数字典整体捕猎存储进系统内部的防篡改审计记录物理表中。

## 5.6 前端状态与基础组件的实现

为了应对管理系统大量表单及持续需要无感驻留特性的页面高强并发特征，对应用作特定的通用二次封装以防后患。

### 5.6.1 Axios 拦截器封装与 Token 无感刷新机制
针对 RESTful 设计架构高安全体系下设定的生命周期极短的 Access JWT Token 带来的频繁掉线痛点；前端改写 Axios 拦截器作了无感接手安排。每当遭遇网络由于 JWT 到期弹回特定的 401 Unauthorized 失效标志；前端利用 `Promise` 在 JS 栈内拦截并挂起暂停这些当前操作：旋即在幕后带上寿命存在的 `Refresh Token` 去向特殊的更签地址发包请求替换取得下一周期的合法的新主凭证；成功换发回填完毕之后，即无缝重启并重新播放原本挂起的工作流，使得终端用户拥有持久保活的丝滑常驻流畅体验。

### 5.6.2 通用数据表格及页面骨架 (`Layout`) 渲染实现
前端业务中包含数百计的查询页展现需求；如照搬重写工作量惊人。利用 Vben-Admin 为开源模版深入结合；所有信息管理栏的重绘采用了通过传导 JSON 协议设置即能被动生成的 `BasicTable` 与 `BasicForm` 高阶组件；内部不仅预打包了懒加载懒渲染分页器，并与平台自己封装包含隐藏控制、自动弹窗等一整套完整逻辑相融合。大幅削减系统页面的前端代码庞大堆砌并极强统一了在这类系统的深色美学操作连贯感受逻辑布局。
