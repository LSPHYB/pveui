# 第二章 系统相关技术介绍

本系统采用前后端分离架构。前端基于 Vue 3、Vite、Pinia、Vben Admin（Ant Design Vue）、xterm.js、noVNC、LogicFlow 和 ECharts 构建；后端基于 Django 5、Django REST Framework、SimpleJWT、Django Channels 和 Daphne 构建，数据库使用 MySQL；底层通过封装 PVE REST API 与 Paramiko、AsyncSSH 等库实现虚拟化资源管理与终端交互。本章对上述技术的原理与特性进行介绍。

## 2.1 前端核心技术

### 2.1.1 Vue 3 与 Vite

Vue.js 是一套用于构建用户界面的渐进式 JavaScript 框架，其核心设计理念是可以被逐步采用——既可以作为简单的视图层库引入，也可以配合周边生态构建完整的单页面应用（SPA）。Vue 3 相较于 Vue 2 最重要的变化是将响应式系统底层由 `Object.defineProperty` 替换为 ES2015 引入的 `Proxy` 代理机制。`Proxy` 可以在语言层面拦截对对象的全部操作（包括属性的增删改以及数组的变更），无需像 `defineProperty` 那样逐属性遍历注册，因而对嵌套对象和数组的响应式追踪更加完整且高效，整体渲染性能也得到显著提升。

Vite 是由 Vue 作者尤雨溪主导开发的下一代前端构建工具，其核心思路是在开发阶段完全基于浏览器原生支持的 ES 模块（ESM）进行按需编译，而非像传统 Webpack 那样在启动时对整个项目进行全量打包。这使得开发服务器的冷启动时间可以控制在毫秒级，且模块热替换（HMR）的速度不会随项目规模增大而劣化。在生产构建阶段，Vite 使用 Rollup 进行打包，并内置 Tree Shaking（摇树优化）支持，可自动剔除未被引用的代码，有效缩减最终产物体积。

### 2.1.2 组合式 API（Composition API）与 Pinia

组合式 API 是 Vue 3 提供的一套全新的逻辑组织方式。与 Vue 2 中基于对象配置块（`data`、`methods`、`computed`、`watch` 等）的选项式 API 不同，组合式 API 允许开发者以函数为单位，将同一功能相关的响应式状态、计算属性和生命周期逻辑集中编写，并通过自定义 Hooks（即以 `use` 为前缀的可复用函数）在多个组件间共享。这种方式避免了选项式 API 中同一业务逻辑被分散于多个配置块所导致的维护困难，在大型应用中尤为突出。组合式 API 同时对 TypeScript 具有天然友好的类型推断支持。

Pinia 是 Vue 官方推荐的全局状态管理库，设计上比 Vuex 更为轻量和直观。Pinia 废弃了 Vuex 中 Mutation 的概念，将状态管理简化为 `State`（响应式状态）、`Getters`（派生状态）和 `Actions`（同步或异步操作）三个部分。每个 Store 以独立模块定义，天然支持代码分割；同时对 TypeScript 提供完整的类型推断，无需额外的类型声明即可获得准确的类型提示和编译期校验。

### 2.1.3 Ant Design Vue 与 Vben Admin

Ant Design 是由蚂蚁集团开源的企业级 UI 设计体系，其 Vue 版本实现为 Ant Design Vue，提供了涵盖布局、表单、表格、弹窗、图标等数十种高质量通用组件。组件遵循统一的设计规范，在视觉风格和交互行为上高度一致，适用于中后台管理系统的快速开发。

Vben Admin 是基于 Ant Design Vue 构建的开源中后台前端解决方案，在组件库之上进一步封装了路由管理、权限控制、动态菜单、布局骨架、主题配置等业务级基础设施，并集成了自动路由加载（`component-loader`）机制与完整的鉴权布局（Layout）框架。开发者可以直接基于其提供的目录结构和约定进行业务开发，从而专注于具体功能实现而非底层架构搭建。

### 2.1.4 xterm.js、noVNC、LogicFlow 与 ECharts

**xterm.js** 是一个基于 Web 标准实现的全功能终端模拟器，运行于浏览器环境中。它支持完整的 VT100/VT220 ANSI 转义序列解析，能够正确渲染颜色、光标控制、滚动缓冲区等终端特性，并提供插件机制支持文本搜索、WebGL 加速渲染等扩展能力。通过与 WebSocket 配合，可以在浏览器中实现流畅的远程 Shell 交互。

**noVNC** 是一个纯 HTML5/JavaScript 实现的 VNC 客户端，无需安装任何本地软件即可在浏览器内访问远程桌面。它通过 WebSocket 将 RFB（Remote FrameBuffer）协议帧传输至前端，利用 HTML5 Canvas 进行渲染，支持键盘鼠标的完整输入映射以及剪贴板同步。

**LogicFlow** 是由滴滴开源的流程图与拓扑图绘制框架，提供了可扩展的节点、边及交互行为定义体系。开发者可以通过其插件机制自定义节点外观与连线规则，支持拖拽连线、节点编辑、历史记录等交互能力，适合构建网络拓扑、流程设计等可视化场景。

**Apache ECharts** 是由 Apache 基金会托管的开源可视化图表库，基于 Canvas 和 SVG 双渲染引擎，支持折线图、柱状图、饼图、仪表盘、热力图等数十种图表类型。ECharts 在处理大规模数据时具有较好的渲染性能，并提供响应式布局、主题定制、数据动画以及流式数据更新等能力，广泛用于监控大屏和数据分析场景。

## 2.2 后端核心技术

### 2.2.1 Django 5 与 MySQL、Django ORM

Django 是基于 Python 的全栈 Web 框架，以"Batteries Included（内置电池）"著称，内置了路由、视图、模板、ORM、表单验证、缓存、认证、管理后台等完整的 Web 开发组件，开发者无需从零集成各类基础设施即可快速构建生产级应用。Django 5 在异步视图支持、数据库访问性能以及表单与模型 API 易用性等方面较前序版本均有所提升。

MySQL 是目前应用最为广泛的开源关系型数据库管理系统之一，以高稳定性、高并发读写性能和成熟的生态工具链著称，适用于存储具有明确结构和关联关系的业务数据。

Django ORM（Object-Relational Mapping，对象关系映射）是 Django 内置的数据库抽象层。开发者以 Python 类定义数据模型，ORM 负责将其映射为数据库表结构，并将 Python 对象的操作自动转换为参数化 SQL 语句执行。参数化查询在底层彻底隔离了 SQL 指令与数据，从机制上杜绝了 SQL 注入风险。ORM 同时支持跨表关联查询、多对多关系、自引用层级结构等复杂模型的简洁表达。

### 2.2.2 RESTful 规范与 Django REST Framework

REST（Representational State Transfer）是一种面向资源的 Web API 设计风格，其核心约束包括：以 URI 唯一标识资源，以标准 HTTP 动词（`GET`、`POST`、`PUT`、`PATCH`、`DELETE`）表达操作语义，以及使用统一的数据格式（通常为 JSON）进行响应。遵循 RESTful 规范的 API 具有良好的可预测性和跨平台兼容性，便于前后端协作和第三方集成。

Django REST Framework（DRF）是 Django 生态中最成熟的 RESTful API 构建扩展，提供了序列化器（Serializer）、视图集（ViewSet）、路由自动生成、权限控制、限流、过滤、分页等完整的 API 开发组件。其中序列化器承担请求数据的字段级验证、嵌套关联数据的解析以及查询结果到 JSON 格式的序列化转换，是 DRF 中处理数据进出的核心组件。

### 2.2.3 JWT 无状态认证与 RBAC 权限模型

JSON Web Token（JWT）是一种基于 JSON 的开放标准（RFC 7519），用于在通信双方之间以紧凑、自包含的方式传递声明（Claims）。一个标准 JWT 由头部（Header）、载荷（Payload）和签名（Signature）三部分组成，服务端通过验证签名即可确认令牌的合法性，无需查询服务器端存储的会话状态，因而具有天然的无状态（Stateless）特性。在前后端分离架构中，JWT 通常以 Bearer Token 形式附加于请求头，支持跨域资源共享（CORS）场景。`djangorestframework-simplejwt` 是 DRF 生态中的 JWT 实现库，提供 Access Token（短期有效）与 Refresh Token（长期有效）的签发、验证与刷新机制。

RBAC（Role-Based Access Control，基于角色的访问控制）是一种将权限分配与用户角色绑定的权限管理模型。其基本结构为：用户被赋予一个或多个角色，角色关联一组权限资源，系统在处理请求时根据当前用户所持角色判断其是否具备对目标资源的访问权限。RBAC 将权限管理从用户层面上升到角色层面，在用户数量庞大、角色类型多样的场景下，相比直接对用户授权具有更低的维护成本和更清晰的权限结构。

### 2.2.4 ASGI 异步架构、Django Channels 与 Daphne

ASGI（Asynchronous Server Gateway Interface）是 Python Web 生态中 WSGI 的异步继任规范，支持 HTTP/1.1、HTTP/2 以及 WebSocket 等长连接协议的并发处理。与 WSGI 的同步阻塞模型不同，ASGI 服务器基于异步事件循环处理请求，可在单进程内以协程方式并发处理大量 I/O 等待任务，而无需为每个连接分配独立线程，适用于需要维持长时间连接的实时通信场景。

Django Channels 是 Django 官方提供的 ASGI 扩展，为 Django 引入了 WebSocket、长轮询等协议的原生支持。Channels 以 Consumer（消费者）为单位处理连接生命周期事件，并通过 Channel Layer（频道层）实现进程间的消息传递与广播，Channel Layer 通常以 Redis 作为消息后端。

Daphne 是 Django Channels 官方配套的 ASGI 服务器，负责接收外部连接并将其按协议类型分发给 Django 应用层处理，支持 HTTP 与 WebSocket 的混合部署。

## 2.3 PVE REST API 封装

Proxmox VE（PVE）是基于 Debian Linux 的开源服务器虚拟化平台，支持 KVM 全虚拟化和 LXC 容器两种虚拟化技术，并提供集群管理、存储管理、网络配置、备份与高可用等完整功能。PVE 对外暴露一套基于 HTTPS 的 REST API（路径前缀为 `/api2/json`），覆盖了节点、虚拟机、容器、存储、网络、任务等所有管理操作，是实现第三方平台对接的标准接口。

PVE API 的认证机制基于票据（Ticket）体系：调用方首先向 `/api2/json/access/ticket` 端点提交凭据，获取具有时效性的 `PVEAuthCookie` 会话票据和用于防止跨站请求伪造的 `CSRFPreventionToken`，后续请求须在 Cookie 和请求头中分别携带这两项凭证。此外，PVE 也支持以 API Token 的形式进行认证，可为 Token 绑定细化的权限范围，适合服务间自动化调用场景。

PVE 中的大多数耗时操作（如克隆虚拟机、在线迁移、磁盘扩容等）均以异步任务（Task）形式执行，API 调用后立即返回任务 ID（UPID），调用方需通过轮询 `/api2/json/nodes/{node}/tasks/{upid}/status` 端点获取任务执行结果。

## 2.4 Paramiko 与 AsyncSSH

SSH（Secure Shell）是一种加密网络协议，用于在不安全网络上建立安全的远程命令执行和数据传输通道。SSH 基于非对称加密完成身份认证与密钥交换，后续通信使用对称加密保护，广泛用于服务器远程管理。

**Paramiko** 是 Python 中成熟度最高的 SSH 协议实现库，提供了 SSH 客户端与服务端的完整实现，支持密码认证、公钥认证、交互式 Shell、命令执行、SFTP 文件传输以及端口转发等功能。Paramiko 基于同步 I/O 模型，适合脚本化的批量运维操作场景。

**AsyncSSH** 是基于 Python `asyncio` 异步框架实现的 SSH 客户端与服务端库，API 设计与 Paramiko 类似，但所有 I/O 操作均为非阻塞的协程调用。在需要同时维护大量 SSH 连接的场景中，AsyncSSH 相较于同步模型的 Paramiko 具有更低的资源开销和更高的并发上限，且可以与 ASGI 框架的事件循环无缝协作。
