# 第四章 系统设计

在完成系统需求分析后，本章进入系统设计阶段。系统设计是将需求分析结果转化为可实施工程方案的关键环节，直接决定后续开发工作的质量与效率。本章将从系统设计原则、系统总体设计与数据库设计三个层次，对基于 PVE 的虚拟化云管平台进行系统化的设计论述。

## 4.1 系统设计原则

为保证系统具备良好的可维护性、可扩展性与安全性，本系统在设计阶段遵循以下核心原则：

**（1）前后端分离原则**：系统采用前后端分离架构，前端基于 Vue 3 框架构建单页应用（SPA），后端基于 Django 5 框架提供 RESTful API 服务。前后端通过标准化 JSON 接口解耦，可独立开发、独立部署，互不干扰，提升了并行开发效率与后期维护的灵活性。

**（2）模块化设计原则**：系统在前端按功能域划分独立路由模块，在后端按业务领域划分独立 Django App（rbac、pve、experiments、chat、audit 等）。各模块职责单一、内聚度高，模块间通过接口依赖而非实现依赖，降低耦合度，便于功能迭代与替换。

**（3）安全性优先原则**：系统采用 JWT 令牌机制进行身份认证，所有需要鉴权的 API 端点均需经过 RBAC（基于角色的访问控制）权限校验。WebSocket 控制台通道使用一次性临时票据（Ticket）防止令牌重放。敏感配置（如 PVE API Token、AI API Key）在数据库中加密存储，禁止在前端响应中明文返回。

**（4）接口标准化原则**：后端所有 API 遵循统一的请求规范（分页、过滤、排序参数格式一致）与响应格式（统一包装层，含 `code`、`message`、`data` 三字段），降低前后端联调成本，方便前端进行全局请求拦截与错误处理。

**（5）用户体验优先原则**：面向非专业运维用户，系统对复杂底层操作（如 PVE 克隆、快照、迁移等）进行图形化封装，提供向导式表单、可视化拓扑编辑器与实时状态反馈，降低操作门槛，减少误操作风险。

## 4.2 系统总体设计

### 4.2.1 系统架构设计

本系统采用三层前后端分离架构，自上而下分为前端交互展现层、后端业务代理层与底层基础设施层，各层通过规范化接口通信，职责清晰、耦合度低。系统架构设计如图 4.1 所示。

```
┌─────────────────────────────────────────────────────────────────┐
│                     前端交互展现层                                │
│   Vue 3 + TypeScript + Vben Admin + Ant Design Vue              │
│   ECharts（数据可视化） │ Cytoscape.js（网络拓扑） │ xterm.js    │
│   noVNC（VNC控制台）    │ Axios（HTTP请求）        │ WebSocket   │
└──────────────────────────────┬──────────────────────────────────┘
                               │  HTTPS REST / WSS
┌──────────────────────────────▼──────────────────────────────────┐
│                     后端业务代理层                                │
│   Django 5 + Django REST Framework + Django Channels (ASGI)     │
│   SimpleJWT 身份认证   │ RBAC 权限中间件              │
│   PVE Async Proxy     │ Celery 异步任务                          │
└──────────────────────────────┬──────────────────────────────────┘
                               │  内网隔离
┌──────────────────────────────▼──────────────────────────────────┐
│                     底层基础设施层                                │
│   Proxmox VE 集群（KVM虚拟机 + LXC容器）  │  MySQL 数据库        │
│                  │  本地大模型服务       │
└─────────────────────────────────────────────────────────────────┘
```

**图 4.1 系统三层架构设计图**

**前端交互展现层**负责向用户呈现可视化界面并响应操作指令。用户在浏览器中通过 Vue 3 渲染的单页应用访问系统，界面框架采用 Vben Admin，组件库选用 Ant Design Vue。数据可视化（仪表盘统计图表）使用 Apache ECharts，网络拓扑可视化采用 Cytoscape.js，LXC 容器 SSH 终端使用 xterm.js，虚拟机图形控制台使用 noVNC（RFB 协议）。前端通过 Axios 处理常规 HTTP 请求，通过 WebSocket 处理 VNC 图形流、SSH 终端代理及 AI 流式回复等长连接场景。

**后端业务代理层**是整个系统的核心枢纽，基于 Django 5 + Django REST Framework 构建，通过 Daphne + Django Channels 支持 ASGI 协议，同时处理 HTTP 与 WebSocket 请求。所有请求经过 SimpleJWT 令牌校验与 RBAC 权限拦截后，分流至对应业务模块：上层业务操作（用户、实验、AI 配置等）通过 Django ORM 直接与 MySQL 交互；底层 PVE 集群操作则由内置的 `PVE Async Proxy` 模块将请求转换为携带 Ticket/CSRF Token 的 PVE 原生 REST 请求，代理提交至 PVE 集群执行，并负责长耗时异步任务的追踪。

**底层基础设施层**位于系统内网隔离区域，包括 Proxmox VE 集群（提供 KVM 虚拟机与 LXC 容器算力）、MySQL 数据库（持久化业务数据）、Redis（作为 Django Channels 的 Channel Layer 与 Celery 消息队列）以及可选的本地大语言模型服务节点，不对公网直接暴露任何端口。

### 4.2.3 系统模块设计

**（1）仪表盘模块设计**

仪表盘是用户登录后的首页，提供平台全局状态的聚合概览。页面采用响应式栅格布局，分为三个区域：顶部展示 4 张统计卡片（PVE 在线节点数、本月 AI Token 消耗量、实验项目总数、用户总数）；中部左侧为 ECharts 折线/柱状双轴组合图展示近 14 天 AI Token 消耗趋势，右侧上方为三个圆形进度条展示主节点 CPU/内存/磁盘使用率（颜色随阈值动态变化：绿<75%、橙<90%、红≥90%），右侧下方展示最近实验列表；底部左侧展示 ISO 镜像与 LXC 模板列表，右侧展示 AI 各模型用量占比的环形饼图。所有数据在页面加载时通过 `Promise.allSettled` 并发请求，任意接口异常不影响其他数据展示。

**（2）系统管理模块设计**

系统管理模块承载平台的基础运维管理功能。用户管理支持账号增删改查，以及与角色、组织的关联绑定；角色管理支持角色创建与权限配置，每个角色可关联若干菜单项与 API 权限，同一用户可被授予多个角色，最终权限取并集；菜单管理维护前端菜单树（支持多层父子嵌套），系统根据当前用户角色动态下发可访问的菜单树，实现前端页面的自动裁剪；权限管理维护 API 级别的权限条目，每条记录包含 HTTP 方法与 URL 正则匹配规则，用于后端接口细粒度拦截；组织管理构建多层级树形组织架构；操作日志通过后端中间件自动记录，仅读不写；系统设置以键值对形式存储可变业务配置，支持不重启服务动态修改。

**（3）PVE 资源管理模块设计**

PVE 资源管理模块是系统的核心功能区，通过 PVE Async Proxy 代理层与 Proxmox VE 集群对接。服务器管理维护多台 PVE 物理服务器的连接配置，支持一键连通性测试。虚拟机管理以表格形式展示所有 KVM 虚拟机，支持创建、电源操作及需二次输入 VMID 确认的危险删除操作；虚拟机详情页采用左侧竖向 Tab 导航，包含概要、控制台（noVNC 图形桌面）、硬件配置、选项、备份管理与快照管理六个子页面。LXC 容器管理功能结构与虚拟机类似，控制台子页面提供基于 xterm.js 渲染的 WebSSH 终端，通过 WebSocket 与后端 Paramiko SSH 代理通信，支持字体、多套主题等个性化配置。网络拓扑包含"实时拓扑"与"拓扑设计"两个 Tab：实时拓扑使用 Cytoscape.js 自动布局渲染从 PVE API 获取的节点与网络连接关系；拓扑设计提供基于 Cytoscape.js 的交互式画布，管理员可自由拖拽节点与连线，构建并持久化自定义网络拓扑图。

**（4）实验教学模块设计**

实验教学模块面向教师和学生两类角色提供差异化视图。教师端实验管理页采用卡片式布局，支持按标题搜索及按状态过滤，每张卡片展示实验基本信息、提交率/批改率/总分统计及操作按钮区（详情、批改、发布/归档、编辑、成绩导出、删除）；实验创建/编辑表单支持上传多格式指导书文件，文件上传后后台自动触发向量化索引任务；提交管理页供教师查看学生提交记录并进行批改，支持退回操作。学生端仅展示已发布的实验列表；报告编辑器页采用左右分栏布局（左侧指导书预览，右侧基于 marked.js 的 Markdown 编辑区），支持附件上传与草稿保存，最终一键提交后系统自动记录时间并判断是否逾期。

**（5）AI 助手模块设计**

AI 助手模块管理平台内集成的大语言模型服务。模型管理支持配置多个大语言模型接入端点，可随时启用/停用指定模型；API Key 管理对 AI API Key 进行集中脱敏管理；额度管理为每位用户单独配置 Token 用量配额；智能体管理为特定实验课程绑定专属 AI Agent，配置关联模型与系统提示词（System Prompt），使不同实验拥有定制化的问答助手；知识库管理展示实验指导书的向量化索引状态，支持管理员手动触发索引重建。用户侧通过浮动 AI 聊天窗口与智能体对话，后端通过 WebSocket 将大语言模型的逐 Token 输出实时推送至前端，实现流式打字效果。
